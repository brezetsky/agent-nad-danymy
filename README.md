# ШІ-агент над даними компанії: як не показати зайвого

Майстер-клас · лектор Брезецький С.О.

Ми будуємо ШІ-агента для вигаданої мережі кав'ярень «Зерно»: менеджер філії ставить питання
природною мовою, а агент сам іде в базу даних і відповідає. Потім ламаємо його — і захищаємо.

Без зовнішніх npm-залежностей: лише Node.js (вбудований SQLite, `fetch` і тест-раннер).

## Підготовка до заняття (10 хвилин, вдома)

1. Встановіть **Node.js 22.13 або новіший** (краще LTS 24): https://nodejs.org — перевірка: `node --version`
2. Встановіть Git і створіть обліковий запис GitHub.
3. Зробіть форк цього репозиторію (кнопка **Fork**, зніміть галочку «Copy the main branch only») і склонуйте його:

```bash
git clone https://github.com/<ваш-логін>/agent-nad-danymy.git
cd agent-nad-danymy
npm run setup        # створює навчальну базу data/company.db
npm run chat         # має відкритися чат із агентом
```

4. **Ключ Gemini (бажано, але не обов'язково).** Відкрийте https://aistudio.google.com/apikey,
   натисніть «Create API key», скопіюйте ключ. Потім:

```bash
cp .env.example .env      # Windows: copy .env.example .env
```

   і вставте ключ у рядок `GEMINI_API_KEY=` у файлі `.env`.
   **Ніколи не комітьте `.env` і не надсилайте ключ у чат.**

Без ключа агент працює в режимі **імітації**: він поводиться як наївна модель і не потребує мережі.
Усе заняття можна пройти в цьому режимі.

## Команди

| Команда | Що робить |
| --- | --- |
| `npm run setup` | Створює (або перестворює) навчальну базу |
| `npm run chat` | Чат від імені Олени — менеджерки київської філії |
| `npm run chat -- petro` | Від імені Петра — менеджера львівської філії |
| `npm run chat -- director` | Від імені директорки мережі (бачить усе) |
| `npm run attacks` | Запускає 8 атак і показує, які спричинили витік (з кроку 2) |
| `npm run attacks -- --verbose` | Те саме з відповідями агента |
| `npm run attacks -- --only 7` | Лише атака №7 |
| `npm run attacks -- --without-prompt-rules` | Атаки без правил у системному промпті (з кроку 3) |
| `npm test` | Тести |

## Кроки майстер-класу

| Крок | Гілка | Що робимо |
| --- | --- | --- |
| 0 | `step-0-start` | База, користувачі, чат. Агента ще немає |
| 1 | `step-1-agent` | Пишемо цикл агента й інструмент `run_sql` — агент «розумний» |
| 2 | `step-2-attacks` | 8 атак: агент видає все, що завгодно |
| 3 | `step-3-prompt-fix` | Захищаємо правилами в промпті — і бачимо, що цього мало |
| 4 | `step-4-code-fix` | Захищаємо в коді: вузькі інструменти, права з сесії, read-only |
| 5 | `step-5-final` | Журнал аудиту й тести безпеки |

Відстали? `git checkout step-N-…` — і продовжуйте з потрібного кроку.

## Політика доступу

Менеджер філії:

1. бачить дані **лише своєї філії**;
2. **не бачить зарплат** співробітників;
3. **не бачить контактів** клієнтів (email, телефон);
4. **нічого не змінює** в базі.

## Структура

```text
data/seed.js        навчальна база: 3 філії, співробітники, клієнти, замовлення
src/users.js        користувачі (у реальній системі — сесія після входу)
src/llm/            Gemini API і режим імітації
src/agent.js        цикл агента
src/tools.js        інструменти, які агент може викликати
src/prompt.js       системний промпт
src/chat.js         консольний чат
attacks/            атаки та автоматична перевірка витоків (з кроку 2)
tests/              тести
```

Усі люди, компанії, email і телефони в базі вигадані.
